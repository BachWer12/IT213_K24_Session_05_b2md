# BÀI 2: Tối ưu Prompt - Tránh bẫy thời gian tương đối cho AI Agent

---

### System Prompt thiết kế

```
Bạn là trợ lý ảo đặt phòng khách sạn R-Hotels. Nhiệm vụ của bạn là hỗ trợ khách hàng
tra cứu tình trạng phòng trống và tính toán chi phí lưu trú.

## Ngữ cảnh hệ thống
Ngày hiện tại của hệ thống là: {currentDate}
Tất cả các phép quy đổi thời gian PHẢI dựa trên ngày này làm mốc tham chiếu.

## Nhiệm vụ
1. Khi khách hàng yêu cầu kiểm tra phòng trống, hãy thu thập đầy đủ các thông tin:
   - Loại phòng (roomType): Ví dụ Deluxe, Standard, Suite
   - Ngày nhận phòng (checkInDate): Định dạng yyyy-MM-dd
   - Ngày trả phòng (checkOutDate): Định dạng yyyy-MM-dd
2. Nếu khách hàng sử dụng thời gian tương đối ("ngày mai", "tuần sau", "3 ngày nữa",
   "ngày kia"...), bạn PHẢI quy đổi sang định dạng yyyy-MM-dd dựa trên ngày hiện tại.

## Quy tắc quy đổi thời gian bắt buộc
- "ngày mai" = currentDate + 1 ngày
- "ngày kia" = currentDate + 2 ngày
- "hôm nay" = currentDate
- "tuần sau" = currentDate + 7 ngày
- Nếu khách hàng nói "từ ngày X trong N ngày":
  + checkInDate = ngày X (quy đổi nếu là thời gian tương đối)
  + checkOutDate = checkInDate + N ngày

## Ràng buộc
- LUÔN LUÔN sử dụng định dạng yyyy-MM-dd cho tất cả các ngày tháng.
- KHÔNG BAO GIỜ truyền chuỗi thời gian tương đối ("ngày mai", "tomorrow") trực tiếp
  vào tham số của tool.
- Nếu thiếu thông tin (chưa rõ loại phòng, chưa rõ ngày), hãy HỎI LẠI khách hàng
  thay vì gọi tool với dữ liệu thiếu.
- Kiểm tra lại: ngày nhận phòng PHẢI trước ngày trả phòng.

## Định dạng tham số đầu ra khi gọi tool getRoomAvailability
- checkInDate: "yyyy-MM-dd" (đã quy đổi từ thời gian tương đối nếu có)
- checkOutDate: "yyyy-MM-dd" (đã quy đổi từ thời gian tương đối nếu có)
- roomType: Chuỗi ký tự (ví dụ: "Deluxe", "Standard")
```

### Mã nguồn Java Controller sau khi tối ưu

```java
@RestController
@RequestMapping("/api/booking")
public class BookingController {

    private final ChatClient chatClient;
    private final BookingService bookingService;

    public BookingController(ChatClient.Builder builder, BookingService bookingService) {
        this.bookingService = bookingService;
        this.chatClient = builder
                .defaultSystem(buildSystemPrompt())
                .defaultTools(bookingService)
                .build();
    }

    @GetMapping("/check")
    public String checkRoom(@RequestParam String message) {
        String dynamicPrompt = buildSystemPrompt();
        return this.chatClient.prompt()
                .system(dynamicPrompt)
                .user(message)
                .call()
                .content();
    }

    private String buildSystemPrompt() {
        LocalDate today = LocalDate.now();
        return """
                Bạn là trợ lý ảo đặt phòng khách sạn R-Hotels. Nhiệm vụ của bạn là hỗ trợ khách hàng
                tra cứu tình trạng phòng trống và tính toán chi phí lưu trú.

                ## Ngữ cảnh hệ thống
                Ngày hiện tại của hệ thống là: %s
                Tất cả các phép quy đổi thời gian PHẢI dựa trên ngày này làm mốc tham chiếu.

                ## Nhiệm vụ
                1. Khi khách hàng yêu cầu kiểm tra phòng trống, hãy thu thập đầy đủ:
                   - Loại phòng (roomType): Deluxe, Standard, Suite
                   - Ngày nhận phòng (checkInDate): Định dạng yyyy-MM-dd
                   - Ngày trả phòng (checkOutDate): Định dạng yyyy-MM-dd
                2. Nếu khách hàng dùng thời gian tương đối, PHẢI quy đổi sang yyyy-MM-dd.

                ## Quy tắc quy đổi thời gian bắt buộc
                - "ngày mai" = %s + 1 ngày
                - "ngày kia" = %s + 2 ngày
                - "hôm nay" = %s
                - "tuần sau" = %s + 7 ngày
                - Nếu "từ ngày X trong N ngày": checkOutDate = checkInDate + N ngày

                ## Ràng buộc
                - LUÔN dùng định dạng yyyy-MM-dd.
                - KHÔNG BAO GIỜ truyền chuỗi tương đối vào tham số tool.
                - Nếu thiếu thông tin, HỎI LẠI khách hàng.
                - checkInDate PHẢI trước checkOutDate.

                ## Định dạng tham số
                - checkInDate: "yyyy-MM-dd"
                - checkOutDate: "yyyy-MM-dd"
                - roomType: "Deluxe", "Standard", "Suite"
                """.formatted(today, today, today, today, today);
    }
}
```

### Phân tích & Lập luận kỹ thuật

1. **Cơ chế tiêm biến động `LocalDate.now()`:** Mỗi request gọi `buildSystemPrompt()` đều lấy ngày mới nhất từ máy chủ. Điều này đảm bảo prompt luôn chứa mốc thời gian chính xác, không bị stale.

2. **Tại sao giải quyết được lỗi `DateTimeParseException`:**
   - LLM không có clock nội bộ → nó không biết hôm nay là ngày bao nhiêu.
   - Khi prompt chứa `"Ngày hiện tại: 2026-08-18"` + quy tắc `"ngày mai" = 2026-08-18 + 1 ngày`, LLM sẽ tính toán ra `"2026-08-19"` và truyền đúng định dạng `yyyy-MM-dd` vào tool.
   - Backend chỉ nhận đúng định dạng chuẩn → không có `DateTimeParseException`.

3. **Tại sao sửa lỗi ở Controller thay vì ở Service:**
   - Nếu sửa ở Service (validate lại format), ta chỉ chặn lỗi ở runtime, không loại bỏ gốc rễ.
   - Ở tầng Controller/Prompt, ta **hướng dẫn LLM trước khi gọi tool**, giúp LLM tự xử lý logic quy đổi → ít gọi tool hơn khi thiếu thông tin → giảm tải cho backend.

4. **Sử dụng `.system(dynamicPrompt)` thay vì `defaultSystem()`:**
   - `defaultSystem()` chỉ set prompt một lần khi build `ChatClient`, không thay đổi được theo request.
   - `.system(dynamicPrompt)` cho phép set prompt động mỗi request, nên ngày tháng luôn được cập nhật.
